# 同桌 · 双模式联机桌游馆

一套可直接运行的房间制网页桌游大厅，目前支持《马尼拉》和经典基础版《璀璨宝石》。两种模式共用登录、大厅、房间码、聊天、断线恢复、服务器主动推送、人机和决策倒计时，并分别使用独立的服务端规则引擎。

首页采用统一的“同桌”桌游馆入口，展示当前开放游戏、支持人数和核心玩法；选择游戏卡后进入大厅会自动预选对应模式。

## 启动

需要 Node.js 20 或更高版本，无需安装第三方依赖。

```bash
npm start
```

本机打开：`http://localhost:4173`

同一局的其他玩家可在同一局域网打开：

```text
http://房主电脑的局域网IP:4173
```

### 临时公网联机（仅用于测试）

项目已在 `tools/cloudflared` 安装 Cloudflare Tunnel。先保持 `npm start` 运行，再打开另一个终端执行：

```bash
npm run tunnel
```

终端会给出一个临时的 `https://*.trycloudflare.com` 地址。把这个地址和房间码发给朋友即可。游戏期间需要保持两个终端运行，并避免电脑休眠。

临时 Tunnel 需要经过中转节点，适合短时测试，不建议用于正式对局。

### 稳定公网联机

推荐把服务部署在靠近玩家的常驻云主机或容器平台。中国大陆玩家若已有 Sealos 等平台的国内区账号，可优先选择国内节点和平台生成的公网地址；否则选择香港节点。其他地区按玩家所在地选择最近节点。部署时：

- 启动命令：`npm start`
- 服务端口：环境变量 `PORT`（默认 `4173`）
- 健康检查：`GET /healthz`
- 持久目录：把可写磁盘挂载到 `/data`，并设置 `DATA_DIR=/data`

项目提供了 `Dockerfile`，可直接构建容器。服务端通过 SSE 主动通知桌面变化；只有在长连接不可用时，浏览器才降级为每 5 秒同步一次。

在已经安装 Docker 的云主机上，可直接运行：

```bash
docker compose up -d --build
```

部署时固定为 **1 个实例**；当前房间状态保存在挂载卷中，多实例会造成玩家落到不同房间状态。平台生成的 HTTPS 公网地址可以直接分享给朋友。

## 游戏模式

在大厅创建房间时先选择模式，座位数量会自动切换：

- 《马尼拉》：3–5 人
- 《璀璨宝石》：2–4 人

公开房间列表与候场房间都会显示当前模式。

## 《马尼拉》已实现规则

- 3–5 人；每人 30₱、2 张秘密股票；3 人局 4 名帮手，4–5 人局 3 名帮手
- 竞拍港务长，退出竞拍后不可返回；允许用股票贷款支撑竞价。当前最高报价会锁定领先者的融资额度，不能通过赎回股票降低支付能力；异常报价会自动作废并重新竞拍，避免卡局
- 港务长每航程可买 1 股，选择 3 种货物，并设置总和为 9 的三个起点
- 人参、肉豆蔻、丝绸、翡翠四类股票与 0/5/10/20/30 黑市轨道
- 三轮派遣与移动；3 人局第一次移动前连续派遣两轮
- 三艘货船、按费用顺序占用的船员位、货物奖金均分
- 港口 A/B/C、船厂 A/B/C 的费用、条件与 6/8/15₱ 回报
- 海盗船长/海盗：第二轮停 13 时登船，第三轮停 13 时抢劫并决定去向
- 小/大领航员：第三次掷骰前移动 1 艘或 2 艘船
- 保险公司：立即领取 10₱，承担所有失败船的修理费
- 抵押股票获得 12₱，支付 15₱ 赎回；破产时支持偷渡客放置
- 抵港货物涨价；任一货物到 30₱ 后按现金 + 股票市值 − 未偿贷款结算
- 服务器生成骰点、服务端校验行动、版本冲突保护、秘密股票按玩家隔离
- 房主可在开局前手动添加/移除人机；人机会自动判断竞拍、布船、派遣、移船、海盗与领航决策
- 建房时可选择每次决策限时 10/20/30 秒；所有玩家同步看到倒计时，超时后服务器随机执行一个合法动作
- 骰子旋转揭晓、海盗登船/抢船、黑市涨价与终局动效由服务端事件统一触发，所有玩家同步播放
- 行动权切换到本人时显示页面闪烁提醒；支持的移动浏览器同时短振动，后台标签页标题会闪烁
- 每次航程结束后暂停在全屏收支结算页，逐人列出期初现金、每笔收入/支出、本轮净变化与结束现金
- 结算页仅能由本轮大领航员确认；没有大领航员时依次由小领航员、港务长确认，人机确认人会短暂停留后自动继续
- 大厅和游戏内均可退出房间；任意一名真人退出后，当前房间与对局立即解散

## 《璀璨宝石》已实现规则

- 经典基础版完整 90 张发展卡与 10 名贵族，按人数设置普通宝石和贵族数量
- 拿 3 枚不同色宝石；库存不足 3 种时拿取所有现存颜色
- 同色拿 2 枚时校验拿取前库存至少为 4
- 明牌预留与牌堆盲预留、每人最多 3 张、黄金库存不足时仍可预留
- 购买明牌或自己的预留卡；永久折扣优先抵费，黄金自动补足任意颜色
- 实体筹码最多 10 枚，超限时由玩家精确选择归还筹码
- 贵族只检查已购买发展卡；同时满足多名时由玩家选择 1 名
- 15 分触发终局并打完当前轮；最终先比较声望，再比较已购买发展卡数量
- 对手看不到玩家预留卡内容；服务端牌堆不会发送给浏览器
- 专属电脑珠宝商策略与超时合法行动托管

## 操作流程

1. 每位玩家输入自己的昵称。
2. 一人创建房间并把 6 位房间码发给其他人。
3. 其他玩家加入；人数不足时房主可添加人机，达到所选模式最低人数后开始。
4. 《马尼拉》的当前可选位置会在棋盘上发光；《璀璨宝石》可从银行、市场与预留区直接行动。
5. 每次航程结束时，所有玩家会看到本轮收支明细；指定领航员确认后才会进入下一航程或最终排名。
6. 房间名称不可重复；进入房间后，必须先退出并解散当前房间，才能创建或加入其他房间。
7. 刷新或短暂掉线不会丢失对局，用原浏览器重新打开即可回来。

## 测试

```bash
npm test
```

测试同时覆盖两种模式。《马尼拉》覆盖 3 人局节奏、人机、全员同步事件、港口顺序、海盗、收支结算、保险、抵押与股票隐私；《璀璨宝石》覆盖完整牌库、人数配额、拿取限制、超限归还、预留隐私、黄金支付、贵族选择、同轮终局、人机与超时托管。

```text
lib/splendor-data.json  90 张发展卡与 10 名贵族数据
server.js            HTTP、房间、会话、SSE 推送 API、静态文件服务
public/               游戏前端
test/                 两种模式与服务端集成测试
Dockerfile            常驻容器镜像
compose.yaml          单实例与持久卷配置
```

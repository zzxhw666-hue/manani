# 正式璀璨宝石 3D 桌面

从大厅选择「璀璨宝石」，创建或加入房间并开始游戏，即默认进入新的 3D 桌面。原先的独立 Demo 保留为设计验收记录。

## 本轮交付

- 同一套实时房间数据驱动桌面，当前登录玩家在下方，对手按相对座次排列在上方，没有正式对局中的换座位开关。
- 发展卡、贵族、银行、自己的筹码、永久折扣、预留牌均取自服务器返回的数据。卡面使用真实费用和声望，而不是 Demo 数值。
- 点击宝石选择，拿不同色或满足库存条件时拿两枚同色；点击市场牌购买或预留；点击牌堆盲预留；点击自己的预留牌购买。
- 沿用服务器的行动校验、版本冲突保护、贵族选择、超额筹码精确归还、倒计时、最后一轮及结算。
- 点击玩家面板或「我的卡牌与筹码」查看已购买卡牌、来访贵族和资源；他人的预留牌只显示数量。
- 顶部记录面板包含行动记录和聊天；「操作列表」提供键盘可访问的按钮入口。
- 页面保留单个 WebGL 场景；离开房间时释放动画循环、材质、贴图、模型与上下文。加载失败或上下文丢失时切到兼容视图，可以重试 3D。

## 每张牌的独立插画

90 张发展卡与 10 张贵族牌共绑定 100 幅不同插画。使用 `public/js/splendor-art.js` 按牌 ID 映射到固定图集单元，洗牌、刷新、多人观看，以及市场 → 预留 → 已购买的移动均不改变插画。兼容视图与详情弹窗也使用同一映射。

上线素材位于 `public/assets/table-club/cards/`：`development-0.jpg` 至 `development-5.jpg` 各包含 15 幅场景，`nobles.jpg` 包含 10 幅肖像。七张图集合计约 5.1 MiB，使用 JPEG 质量 82 转码，不改变构图；生成的原始 PNG 保留在开发目录 `artifacts/card-art-sources/`，不随网页下载。

插画由内置 imagegen 生成（非 API/CLI），完整提示词与输出映射见 `docs/splendor-art-prompts.json`。贵族肖像是虚构人物，不对应真实历史人物。

## 验证方式

运行 `npm test`：包含规则回归、卡图完整性与唯一性、2–4 人主视角、支付预览等。

浏览器验收需 Node 22+，以及开启远程调试的 Chrome。请只在隔离的测试服务器上运行，它会创建两个临时会话与一个测试房间，结束时只解散自己创建的房间。

```sh
task_data_dir=$(mktemp -d /tmp/splendor-acceptance.XXXXXX)
PORT=4205 DATA_DIR="$task_data_dir" node server.js
# 另一个终端：
node tools/check-splendor-live.mjs http://localhost:4205 http://localhost:9224 /tmp/splendor-live.png
```

测试分两层：双浏览器独立会话对真实服务器验证 SSE、拿取、明牌与盲预留、隐私和刷新；受控界面场景验证购买提交、归还数量、贵族选择、回合失效、结算、三档桌面尺寸、兼容视图和资源释放。另对浏览器实际解码的 100 个插画单元逐一检查，避免只是不同文件名却复用同一张图。

本轮未改动马尼拉规则或璀璨宝石服务器规则，未接入新的在线服务。
